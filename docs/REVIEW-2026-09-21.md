## What is solid

- **The approval gate itself.** `launch_checks` is a pure list of refusals, tested for each one (15); `approve` writes a row and rents nothing; `propose` cannot be tricked by parked rows (`--speaker` test); the estimate is stored per batch so a later RTFX cannot rewrite history. The cap check uses the `spend` ledger, which survives restarts.
- **`create_pod`'s reconcile path.** The pods row is inserted *before* the API call under a provisional id; on any error it queries RunPod for `ytpt-<id>`, adopts and tears down what it finds, and if even that fails leaves the row `ORPHAN` with a loud message. This is the right shape.
- **Claim semantics.** Every worker takes a row with a conditional `UPDATE … WHERE status = ?` and writes an `events` row in the same transaction; rowcount 0 means "someone else has it, move on". Two downloaders cannot hold one video (tested).
- **Data safety.** Nothing under `output/` is deleted by code — the only `unlink`s are `.tmp.opus` files that failed verification, a `.write-test`, and the simulated/demo outputs (`simulate.py`, `demo_state.py`). Every final file is written atomically (`.tmp` + `os.replace`/`Path.replace`) and verified with `ffprobe` before the row moves. `host_enroll.py --apply` backs each original up to `output/whisper_pre_enroll/` once and never overwrites the backup. `state.py migrate` is add-only and copies the DB (SQLite online backup, WAL included) first; `connect()` adds missing columns on every open. `load_db.py` and `load_episodes.py` rebuild only their own tables and build on local scratch.
- **Episode time offsets.** `window_start_s` comes from `episodes.start_s` (the padded, cue-snapped bound that was actually cut) via `build_manifest`; the Granicus path corrects for the HLS segment-boundary early start (`a_actual = b − d`); the transcript carries `episode_start_s`; QA windows the caption reference by `window_start_s`. Consistent end to end (tested in 19).
- **Statistics.** G² and Hardie's log ratio are textbook-correct with the zero-count conventions stated; the bootstrap resamples videos, not tokens (tested to be wider than the naive interval); KWIC is whole-word with the node removed before counting collocates. Significance stars are labelled uncorrected.
- **Secrets.** `.env` is parsed with `setdefault` and never printed; `HF_TOKEN` and the SSH public key reach the pod only inside the create request body; `gpu_bootstrap.sh` is tested for `set -x`/`echo $HF_TOKEN`; the notifier's dry run prints `<discord webhook>`, not the URL; classifier prompts quote caption text inside `<transcript>` tags and the model's `contains_instructions` flag is logged (AGENTS.md rule 5).
- **Untrusted text.** Titles are parsed by four date regexes only; Granicus HTML by regexes, never executed; caption text is counted, never shown to anything but the pinned classifier.

## What changes for Puck

1. **After a YouTube bot check the downloader stays down.** It no longer comes back by itself every 10 minutes. Resume: tell the supervisor `resume`, or `launchctl kickstart -k gui/$(id -u)/com.ytpt.downloader`.
2. **Run `launch` detached, always** — `nohup … launch bN > output/batches/bN/launch.log 2>&1 &` (runbook updated). Ctrl-C/SIGTERM now clean up properly; SIGKILL still cannot, and the dashboard will call the pod an orphan after 13 h.
3. **`teardown <pod_id>` is safe to repeat.** Running it on a pod already recorded as terminated does nothing.
4. **Granicus refusals stop `episodes.py`** the way YouTube ones do (exit 3, message); re-run when the host is answering again.
5. **`corpus.sqlite` episode tables contain names** until the #15 redaction step exists (M8).
6. Open for a decision: M7 (`reconcile` command), L1 (Bearer header for RunPod), L6 (downloader fragment retries).
